Olum では「render」関数を呼ぶことはありません。[`state`](/docs/state) や[ストア](/docs/store/global-store)を変更すれば、ページが更新されます。このページでは、その間に何が起きているかを説明します。

## 変更の後に起きること {#what-happens-after-a-change}

1. **変更が検知されます。** `state` を（どの深さでも）変更すると、そのコンポーネントに更新が必要だという印が付きます。ストアを変更すると、そのストアを使っているすべてのコンポーネントに印が付きます。
2. **更新はまとめられます。** 印の付いたコンポーネントはすべて、あなたのコードが終わった直後に **1 回だけ**更新されます。`state.a++; state.b++` も、100 行を移動する `splice` も、1 回の更新です。
3. **新しい HTML は画面外で組み立てられます。** この時点ではページはまだ何も変わっていません。
4. **差分だけが適用されます。** Olum は新しい HTML とページを比較し、違う部分だけを変更します。変わっていない要素には触れません。

親と子が同時に更新を必要とする場合、更新されるのは**親だけ**です（それによって子も更新されます）。

## 更新を経ても残るもの {#what-survives-an-update}

変わっていない要素はそのままなので、ブラウザがそれらに保持しているものはすべて残ります：

- フォーカス、テキストカーソル、テキストの選択範囲
- スクロール位置（スクロール可能なボックスの中も含む）
- 再生中の `<video>` や `<audio>`、実行中の CSS アニメーションやトランジション
- `<iframe>` や `<canvas>` の内容
- テンプレートが設定していないもの。たとえばステートにバインドされていない入力欄の値
- イベントリスナー（リスナーが置き換えられるのは、そのハンドラや、ハンドラで使われている値（ループ変数など）が変わったときだけです）

:::tip
だから Olum には、覚える必要のある「フォーカスを保持する」オプションがありません。遠慮なく更新してください。
:::

## 更新が必要なコンポーネントだけが更新される {#only-components-that-need-it-update}

- **使われていないキーはスキップされます。** Olum は、各テンプレートがどの `state` のキーを読んでいるかを知っています。テンプレートで使われていないキー（ハンドラや `onMount` でしか使っていないキーなど）を変更しても、何も更新されません。
- **ストアの利用は自動的に追跡されます。** コンポーネントはテンプレートでストアを*読む*だけで、そのストアを購読します。ストアに書き込むだけのコンポーネントが、ストアによって更新されることはありません。
- **削除されたコンポーネントはスキップされます。** すでになくなったコンポーネント（ルートの変更、閉じた `<if>`）の保留中の更新は破棄されます。

## key：どの要素がどれか {#keys-which-element-is-which}

リストが変わると、Olum は古い要素と新しい要素を対応させます：

- コンポーネントは同一性を保つので、再利用され、ステートも保たれます。
- 普通の要素は、`key="{item.id}"` か、その [`<for>`](/docs/loops) の `key` で同一性を持たせられます。
- key のある要素は作り直されるのではなく**移動**されます（ブラウザが `moveBefore` に対応していればそれを使うので、再生中の動画でさえ残ります）。
- key のない要素は位置で対応させます。それでも Olum は単純な挿入や削除なら見抜けるので、その下の行が作り直されることはありません。

key なしでの大きな変更（並び替え、複数行の絞り込み）は、そのやり方では対応させられません。行は移動するのではなく、隣の項目のデータで描き直されます。`key` を付ければ解決します。[制限事項](/docs/limitations)を参照してください。

## 入力欄が誤ってリセットされることはない {#inputs-are-never-reset-by-accident}

Olum が入力欄に `value` や `checked` を書き込むのは、**テンプレートの**値が変わったときだけです。そのため、関係のない更新で入力中の内容が消えることはありませんが、ステートにバインドされた入力欄はステートが変われば変わります。フォーカス中の入力欄に書き込む場合も、カーソルは元の位置のままです。`<select>` は、テンプレートが `selected` を動かさない限り、ユーザーの選択を保ちます。[双方向バインディング](/docs/two-way-binding)を参照してください。

## 変更直後にページを読み取る {#reading-the-page-right-after-a-change}

更新はまとめられるので、変更した次の行ではページはまだ古いままです。`flushUpdates()` で保留中の更新をすぐに適用できます：

```js
import { flushUpdates } from "olum";

state.count++;
flushUpdates();                           // apply pending updates now
host.querySelector("span").textContent;   // up to date
```

いつ呼んでも安全です（保留中のものがなければ何もしません）。主にテストや、新しい要素のサイズを測る必要があるときに役立ちます。

:::note
更新が失敗した場合、Olum は `patch failed — falling back to full re-render` を出力し、コンポーネントを一から作り直します。ページは正しいままですが、フォーカス、メディア、スクロールはリセットされます。この警告が出たら、バグとして報告してください。
:::
